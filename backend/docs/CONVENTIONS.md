# Orbit backend conventions

This is the contract every module follows. Read it fully before writing code. If something here is
wrong or missing, say so in your report instead of silently diverging.

Go module path: `github.com/sapionic/orbit/backend` · Go 1.27 · Postgres 17 + PostGIS · Redis 7

## 1. Layout

```
backend/
├─ cmd/
│  ├─ api/        # HTTP server (thin main around internal/app)
│  ├─ worker/     # River workers + event subscribers (thin main around internal/app). `-ping` = smoke event
│  ├─ migrate/    # goose (embedded SQL) + River's own migrations. `migrate up|down|status`
│  ├─ seed/       # dev seed data (stub; the integrator fills it)
│  └─ devtoken/   # mints a dev JWT for curl: `make token KIND=ho ROLE=ops`
├─ migrations/    # goose SQL, one file per module, numbered in dependency order. Schema is owned centrally.
│                 # embed.go exposes them as migrations.FS.
├─ internal/
│  ├─ app/        # wire.go builds every module and connects ports; ONLY the integrator edits it.
│  ├─ platform/   # shared infrastructure, no business logic (see section 3)
│  └─ <module>/   # identity, geo, farmers, masters, visits, messaging, sync, audit
├─ sqlc.yaml      # one entry per module (already present for every module)
└─ docs/
```

Contracts live at the repo root: `contracts/openapi/<module>.yaml`, one OpenAPI 3.0.3 document per module.
`contracts/openapi/_shared_components.yaml` holds the error/pagination components every spec copies verbatim.

Reference module: `internal/audit` is complete (spec, handler, service, queries, unit + HTTP + integration
tests). Copy its shape.

## 2. Module anatomy

Every module is a package under `internal/<module>/` with this shape. Split large files by area
(`service_plots.go`, `handler_admin.go`); keep each file focused and under ~400 lines.

```
internal/<module>/
├─ module.go          # type Module; New(deps platform.Deps, ports *Ports) *Module; Service() *Service;
│                     # Mount(r chi.Router); and only the hooks that apply:
│                     # RegisterWorkers(w *river.Workers); RegisterCommands(reg *commands.Registry);
│                     # RegisterSubscribers(bus *events.Bus); RegisterSnapshot(reg *territory.Registry)
├─ ports.go           # interfaces this module needs from OTHER modules (section 5). Consumer-defined.
├─ model.go           # domain types returned by the service
├─ service*.go        # business rules. Takes context, returns domain types or apperr errors.
├─ handler*.go        # implements the generated StrictServerInterface; maps DTO <-> domain. No SQL here.
├─ api.gen.go         # GENERATED by oapi-codegen from contracts/openapi/<module>.yaml. Never hand-edit.
├─ oapi-codegen.yaml  # codegen config (package <module>, models, chi-server, strict-server, embedded-spec)
├─ generate.go        # //go:generate line that runs oapi-codegen (run via `make gen`)
├─ queries/*.sql      # sqlc queries for THIS module's tables only
├─ store/             # GENERATED by sqlc. Never hand-edit.
├─ commands.go        # sync command handlers (if any)
├─ events.go          # event subscribers (if any)
├─ jobs.go            # River workers (if any)
└─ *_test.go
```

Wiring rules
- `New` receives `*Ports` (a pointer). The integrator fills the fields in `internal/app/wire.go` AFTER every
  module is constructed, so ports may form cycles (identity <-> farmers, farmers <-> visits). Never read
  ports in `New`; read them in service methods (`s.ports.Geo.GetVillages(...)`).
- `Service()` returns the module's `*Service`; the integrator passes it to other modules' ports.
- Hooks are discovered by interface assertion (`internal/app/hooks.go`): implement a hook and it is wired,
  no edit to wire.go needed. A method named `Mount` or `Register*` with the wrong signature panics at startup.
- Mount pattern (copy from `internal/audit/module.go`): `NewStrictHandlerWithOptions(h, nil,
  StrictHTTPServerOptions{RequestErrorHandlerFunc: httpx.RequestErrorHandler, ResponseErrorHandlerFunc:
  httpx.ResponseErrorHandler})` then `httpx.MountSpec(r, GetSwagger, func(r chi.Router) { HandlerWithOptions(h,
  ChiServerOptions{BaseRouter: r, ErrorHandlerFunc: httpx.RequestErrorHandler}) })`. Requests are validated
  against the module's spec (kin-openapi) before the handler runs.
- Handlers return service errors unchanged (`return nil, err`); `httpx.ResponseErrorHandler` writes them in
  the shared shape. Only return typed 4xx response objects if you need a non-error 4xx body.
- Services that need test fakes declare a small `queries` interface with just the store methods they use
  (see `internal/audit/service.go`) instead of depending on the whole generated `store.Querier`.
- The `sync` module's package is named `sync`; import the standard library as `gosync "sync"` there.

Rules
- A module reads and writes only its own tables (table ownership = the migration file it's in). To use
  another module's data, call it through a port. Foreign keys across modules are fine.
- Handlers never contain business rules; services never see HTTP types.
- Money is never stored as float. Paise as int64.
- Time: `timestamptz` in DB, `time.Time` in UTC in Go, RFC 3339 in JSON. Dates as `YYYY-MM-DD`.
- IDs: UUIDv7 via `ids.New()`. IDs created offline arrive from the phone and are accepted as-is.
- Phone numbers are normalised to E.164 (`+91XXXXXXXXXX`) with `phone.Normalize`.
- Telugu text fields are `*_te`; English `*_en` or plain. Farmer-facing responses include both.
- No competitor brand names anywhere: advice references a Shanmukha `sku_id` or nothing (salt only).

## 4. HTTP surfaces and auth

Paths in every spec are absolute. The surface guard middleware enforces token kind by prefix:

| Prefix | Who | Token kind |
|---|---|---|
| `/v1/auth/*` | anyone | none (login, OTP, refresh). A valid bearer token, if sent, is attached as the principal. |
| `/v1/farmer/*` | farmer app | `farmer` |
| `/v1/fa/*` | FA app | `fa` (device must not be revoked) |
| `/v1/admin/*` | HO portal | `ho`; roles checked in the service with `auth.RequireRole` |
| `/v1/web/*` | farmer web pages | signed link token (`kind=web`, `deps.Tokens.IssueLink`), as `?t=` or bearer |
| `/hooks/*` | partners | provider signature, checked in the handler |
| `/healthz`, `/readyz` | infra | none. readyz: 503 if Postgres is down; 200 `degraded` if only Redis is down. |
| `/dev/files/*` | dev only | HMAC-signed URL from `storage.Local` |

Guard checks after the token is verified (`RouterConfig.CheckPrincipal`, provided by identity, cached in Redis with a
Postgres fallback): farmer and FA tokens from a revoked device get 401 `device_revoked`; HO tokens whose session was
revoked or whose user was disabled get 401 `session_revoked`. Tokens carrying `Principal.MustChangePassword` (claim `pwc`,
FA and HO temp passwords, which expire after 72 h) get 403 `password_change_required` everywhere except
`/v1/fa/me/password`, `/v1/admin/me/password`, `/v1/admin/me` and `/v1/auth/*`; after changing the password the client
refreshes to get a clean token. Request bodies are capped (`HTTP_MAX_BODY_BYTES`, 2 MiB; the sync batch and CSV import
opt in to `HTTP_LARGE_BODY_BYTES`, 5 MiB via `RouterConfig.BodyLimits`); over the cap is 413 `payload_too_large`
(`apperr.TooLarge`).

HO roles: `admin`, `agronomy`, `finance`, `ops`. Admin can do everything except approve agronomy content.
Wrong token kind for a surface is 403; missing/invalid/expired token is 401 (`details.reason = "expired"` when
expired).

Area scope: an HO user with non-empty `DistrictIDs` sees only those districts; services filter by it
(`p.HasAreaScope()`, `p.CanSeeDistrict(id)`).

Errors use one JSON shape everywhere:
```json
{ "error": { "code": "conflict", "message": "Plot was changed by HO", "details": { ... } } }
```
Standard codes: `unauthorized` 401, `forbidden` 403, `not_found` 404, `validation_failed` 400 (with
`details.fields: {name: reason}`; also produced by spec validation), `invalid_request` 400 (unparseable
request), `invalid_cursor` 400, `method_not_allowed` 405, `rate_limited` 429 (+ `Retry-After`),
`unavailable` 503, `internal` 500 (no detail leaked). Conflicts use a specific code (`version_mismatch`, ...).
Every spec copies the shared `ErrorResponse` schema and responses from `contracts/openapi/_shared_components.yaml`.

Lists use `?limit=&cursor=` and return `{ "items": [...], "next_cursor": "..." | null }` (keyset on
`(created_at, id)`, or another `(timestamp, id)` pair). Use the `paging` package; the query fetches
`limit + 1` rows (see `internal/audit/queries/audit_log.sql` and `service.go`). The cursor is opaque.

## 5. Cross-module ports

The consumer declares the interface in its own `ports.go` using exactly these signatures. The provider
implements the method on its `*Service` with the same signature. The integrator wires them in `internal/app/wire.go` (`p.Farmers.Geo = m.Geo.Service()`).
Value types passed across ports live in **`internal/xmod`** (`xmod.Village`, `xmod.FarmerSummary`, ...), never in the
provider package, so modules never import each other (farmers <-> visits would be an import cycle). A module may import
`xmod` and `platform/...` only, never another module. `xmod` is owned by the integrator: don't change it; if a field is
missing, say so in your report and work around it.

## 6. Sync commands (FA offline)

The FA app sends `POST /v1/fa/sync/commands` with a batch: `[{id, type, payload, client_created_at}]`.
The sync module stores each command in `sync_commands` once (the `id` is the idempotency key; a repeat
returns the stored result) and dispatches by `type` to a handler registered by the owning module.
Handlers run inside their own transaction and must be idempotent for the same command ID.

`commands.Result{Status: applied|merged|conflict|rejected, EntityID uuid.UUID, MergedInto *uuid.UUID, Conflict *Conflict{Field, Yours, Theirs any}, Error *string}`
(helpers: `commands.Applied(id)`, `Merged(id, into)`, `Conflicted(id, c)`, `Rejected(id, reason)`).

**Which farmers an FA may act on (one rule everywhere):** after resolving merge aliases, the farmer's
`assigned_fa_id` must be the FA. The only exception is `EnrolFarmer` merging into an existing phone: allowed
when the farmer is unassigned (the enrolling FA then becomes the assigned FA, and the village must be in the FA's
territory) and rejected as `registered_with_another_fa` (no farmer ID in the result) when assigned to someone else.
The snapshot contains exactly the farmers an FA may act on. Other modules check through
`Farmers.ResolveFarmerForFA`. Rejection reasons the app should show: `registered_with_another_fa`,
`not_in_your_area`. Before enrolling, the app can call `GET /v1/fa/farmers/lookup?phone=` (status `new | mine |
unassigned_in_my_area | outside_my_area | other_fa | deactivated`; farmer ID only for `mine` and
`unassigned_in_my_area`; rate limited and audited). Snapshot fields to know: `farmers[].consent_pending` (no programme
consent yet: capture it with `RecordConsent`) and `visits[].issues[].advice_status` (`resolved | unresolved`; `salt_id`
is null when unresolved).

**Consent proof (FAR-04):** the FA app calls `POST /v1/fa/consent-otp/request` and `/verify` (identity) while
online; verify returns `otp_proof`, a token from `deps.Tokens.IssueConsentProof` (7-day TTL) bound to the FA and
the phone. `EnrolFarmer.consent.otp_proof` and `RecordConsent.otp_proof` are checked with
`deps.Tokens.VerifyConsentProof` (FA and phone must match). No valid proof means no `fa_otp` consent row.

**Farmer photos:** the FA app gets a presigned PUT from `POST /v1/fa/farmers/{farmer_id}/photo/upload-url` (the farmer
ID may be the offline-minted one) and sends the returned key as `photo_key`. Keys must sit under
`farmers/{farmer_id}/`: `UpdateFarmer` rejects any other key; `EnrolFarmer` drops it (recorded in the audit meta) so the
enrolment and the commands queued behind it still apply.

**Consent in the farmer app** (`/v1/farmer/me/consents`) works for `pending_profile` farmers too, so sign-up can take
consent before the village is picked (FAR-04).

**Errors:** `Registry.Dispatch` also turns Postgres data and constraint errors (SQLSTATE classes 22 and 23) into
`rejected`, so a bad payload can never block an FA's queue; the sync module additionally rejects a command after
repeated infrastructure failures (see the sync module).

Handler: `func(ctx context.Context, p auth.Principal, cmd commands.Command) (commands.Result, error)` where
`Command{ID, Type, Payload json.RawMessage, ClientCreatedAt *time.Time}`. Prefer
`commands.Typed(func(ctx, p, cmd, payload MyPayload) (commands.Result, error))`. `Registry.Dispatch` turns
unknown types, undecodable payloads and apperr Validation/NotFound/Forbidden/Conflict errors into `rejected`
results; any other error is an infrastructure failure the sync module retries.

| Type | Owner | Payload (JSON, snake_case) |
|---|---|---|
| `EnrolFarmer` | farmers | `farmer_id, phone, name, name_te?, language, village_id, photo_key?, consent{purposes[], otp_proof?, audio_played, notice_version}` → `merged` with `merged_into` if the phone exists (see the rule above) |
| `RecordConsent` | farmers | `farmer_id, purposes[], otp_proof, audio_played, notice_version` (consent captured after an enrolment that had no proof) |
| `SavePlot` | farmers | `plot_id, farmer_id, label, boundary_geojson?, pin{lat,lng}?, area_acres, area_source, gps_accuracy_m?, expected_version?` |
| `StartSeason` | farmers | `season_id, farmer_id, plot_id, season_code, crop_id, sowing_date?, previous_crop_id?` |
| `UpdateFarmer` | farmers | `farmer_id, expected_version, fields{name?, name_te?, language?, village_id?, photo_key?}` → `conflict` on version mismatch |
| `PlanVisit` | visits | `visit_id, farmer_id, plot_id, season_id, planned_for, planned_slot, purpose?` |
| `LogVisit` | visits | `visit_id, farmer_id, plot_id, season_id, visited_at, location{lat,lng}?, farmer_present, stage_id?, notes?, issues[{issue_visit_id, issue_id, severity, advisory_rule_id}], photos[{photo_id, content_type}], next_visit?{visit_id, planned_for, planned_slot}`. `advisory_rule_id` is the rule (salt, FA-09) the FA picked from the snapshot; an issue whose rule doesn't check out is kept on the visit as unresolved, never rejecting the visit. |
| `CancelVisit` | visits | `visit_id, reason?` |
| `CloseCallback` | visits | `callback_id, note?` |
| `AckAlert` | messaging | `alert_id` |

## 7. Domain events (`internal/platform/events/catalog.go`)

Published inside the writer's transaction (`deps.Events.Publish(ctx, tx, events.X{...})`; unknown names fail);
delivered at least once by the worker, so subscribers must be idempotent. The worker fans each event out to one
River job per subscriber, so subscribers retry independently. Subscribe with a stable subscriber name
(`events.Handle(bus, "messaging.welcome_sms", fn)`); the name keys delivery jobs. `events.MetaFrom(ctx)` gives
the event ID, name, time and attempt. `system.ping` exists for smoke tests only.

| Name | Payload | Publisher | Subscribers |
|---|---|---|---|
| `farmer.registered` | `{farmer_id, village_id?, source, enrolled_by_fa_id?}` | farmers | messaging (FA + HO new-farmer alerts, welcome SMS) |
| `farmer.profile_completed` | `{farmer_id, village_id}` | farmers | messaging (alert FA when a self sign-up picks a village) |
| `farmers.reassigned` | `{farmer_ids[], from_fa_id?, to_fa_id}` | farmers | visits (move open planned visits and callbacks), messaging (SMS new FA name) |
| `visit.logged` | `{visit_id, farmer_id, plot_id, season_id, fa_id}` | visits | messaging (advice notice + SMS to farmer) |
| `callback.requested` | `{callback_id, farmer_id, fa_id}` | visits | messaging (FA alert) |
| `masters.published` | `{kind, version}` | masters | masters (cache invalidation) |
| `device.revoked` | `{device_id, subject_kind, subject_id}` | identity | sync (drop cached snapshot) |

## 8. Territory snapshot

`GET /v1/fa/sync/snapshot` returns everything the FA app keeps offline, gzipped, with an ETag.
The sync module asks the `territory.Registry` for a resolver and providers:
- Resolver (set by farmers in `RegisterSnapshot`): `reg.SetResolver(func(ctx context.Context, faID uuid.UUID) (territory.Scope, error))`,
  `Scope{FAID, VillageIDs, FarmerIDs []uuid.UUID}`.
- Providers: `reg.Register(section string, func(ctx context.Context, s territory.Scope) (any, error))`. Sections
  (constants `territory.SectionFarmers` etc.): `farmers`, `plots`, `seasons` (farmers module), `visits`,
  `callbacks` (visits), `alerts` (messaging), `masters` (masters), `villages` (geo: the villages in the FA's area, with mandal/district names, for offline enrolment).
- The sync module calls `deps.Territory.Build(ctx, faID) (map[string]any, error)` and reads the version with
  `territory.Version(ctx, deps.Pool, faID)`.
- Cache key `scope:{fa}:v{territory_version}:m{masters_version}`. Any module that writes data inside a
  territory calls `territory.Bump(ctx, tx, faIDs...)` in the same transaction.

## 9. Audit

Every state-changing service method writes `audit.Record(ctx, tx, audit.Entry{Action, EntityType, EntityID,
FarmerID, PlotID, SeasonID, Before, After, Meta})` in the same transaction (uuid.Nil = NULL; Before/After/Meta
are JSON-marshalled, never include secrets). With no principal on ctx the actor is `system`. Action names are
`<module>.<verb>` in past tense (`farmers.enrolled`, `masters.rule_approved`, `identity.fa_login_issued`).
Reads of sensitive data (later: identity checks) are audited too.

## 10. Testing

- Unit tests for services with fakes for ports.
- Integration tests run against Postgres from `dev/docker-compose.yml` using `TEST_DATABASE_URL`
  (database `orbit_test`); they skip when it is unset. Use `testutil.NewDB(t)` which migrates (goose + River,
  once per process) and truncates every table before the test, then `testutil.NewDeps(t, pool)` for a full
  `platform.Deps` (no Redis, insert-only River, temp-dir storage, log SMS/push, discard logger).
- DB tests are serialised across packages with a Postgres advisory lock, so `go test ./...` is safe. Don't use
  `t.Parallel()` in DB tests. If a migration seeds rows, add them to `reseedSQL` in `testutil/db.go`.
- Principals and HTTP: `testutil.HO(auth.RoleOps)`, `testutil.FA()`, `testutil.Farmer()`, `testutil.Ctx(p)`
  (context with principal + request ID), `testutil.Token(t, tokens, p)`, `testutil.Router(tokens, m.Mount)`
  (real middleware stack). See `internal/audit/handler_test.go`.
- `make test` runs everything; `make check` runs `gofmt`, `go vet`, codegen-up-to-date checks and tests.

## 11. Generated code

- `make gen` runs sqlc and oapi-codegen (`go generate ./internal/...`) for every module. Generated files are committed;
  `make check` fails if they are stale.
- Never edit `api.gen.go` or `store/`. Change the spec or the query, then regenerate.
- sqlc types: `uuid` -> `uuid.UUID` (nullable `uuid.NullUUID`), `timestamptz`/`date` -> `time.Time` (nullable
  `*time.Time`), nullable text/int/bool -> pointers, `jsonb` -> `json.RawMessage`, `inet` -> `netip.Addr`,
  `numeric` -> `pgtype.Numeric`. Optional filters: `sqlc.narg('x')::type IS NULL OR col = sqlc.narg('x')`.
- PostGIS: sqlc does not understand geography. Read it as GeoJSON text: `ST_AsGeoJSON(col)::text AS col_geojson`;
  for a nullable column use `COALESCE(ST_AsGeoJSON(col)::text, '') AS col_geojson` and treat `''` as absent
  (sqlc cannot infer nullability through casts). Write with
  `ST_GeomFromGeoJSON(sqlc.narg('boundary_geojson')::text)::geography`. Cast scalar PostGIS results
  (`ST_Area(...)::float8`). Don't `SELECT *` from tables with geography columns (they map to `interface{}`).
- oapi-codegen: `format: uuid` -> `openapi_types.UUID` (= `uuid.UUID`), `date-time` -> `time.Time`, optional
  or nullable fields -> pointers. Mark always-present-but-nullable response fields as `required` + `nullable`.
- Specs carry no `servers` block; paths are absolute.

## 13. Schema notes

- `devices.push_token text` was added (00002) so identity can store FCM/APNs tokens for messaging.
- OTP challenges live in Postgres (identity adds the table in its reserved migration), not only Redis, so sign-in
  works with Redis down.
- Migrations: never edit 00001-00008. Each module that needs schema changes adds ONE file with its reserved number:
  identity `00009`, geo `00010`, farmers `00011`, masters `00012`, visits `00013`, messaging `00014`, sync `00015`
  (name it `000NN_<module>_<what>.sql`). goose runs with out-of-order allowed, so the numbers can land in any order.
  A migration may only create/alter the module's own tables (section 2 ownership).
- Second round of numbers (review fixes): identity+platform `00016`, farmers `00017`, masters `00018`,
  visits `00019`, messaging `00020`, sync `00021`, geo `00022`.
- Config added in the review round: `HTTP_MAX_BODY_BYTES`, `HTTP_LARGE_BODY_BYTES`, `STORAGE_PROVIDER` (only `local`
  exists; refused in prod, as are `SMS_PROVIDER=log` and `PUSH_PROVIDER=log`), `TOTP_ENC_KEY` (AES-GCM key for
  `ho_users.totp_secret`, stored as `v1:<base64>`; required in prod; dev derives one from `JWT_SECRET`).
- `ratelimit` windows are at most `ratelimit.MaxWindow` (24 h); expired counters are purged by `identity.maintenance`.
- **From now on** the parallel-agent number reservations are retired: a new migration takes the next number after the
  highest file (today `00026`; `00022`-`00025` were reserved and never used, which goose allows). Never edit an applied
  migration.
- Config added in gap-fix round 2: `FARMER_WEB_BASE_URL` (SMS/WhatsApp notice links; defaults to `PUBLIC_BASE_URL`),
  `OTP_SMS_APP_HASH` (Android SMS Retriever line), `APP_{MIN_VERSION,LATEST_VERSION,STORE_URL,FLAGS}_{FARMER,FA}`
  (served by `GET /v1/auth/app-config` and the heartbeats), `WORKER_HEALTH_ADDR` (worker `/healthz` and `/readyz`,
  default `:8081`). `cmd/migrate` needs only `DATABASE_URL` (`config.LoadDatabase`). An empty `REDIS_URL` now really
  runs without Redis.
- Every SMS wording lives in `internal/platform/sms/templates.go`, one named DLT template ID per wording and language
  (19-digit placeholders until DLT registration). A test fails if two wordings share an ID.
- One container image (`backend/Dockerfile`, `make image`) carries `api`, `worker`, `migrate` and `seed`.
- Periodic jobs: a module exposes `func PeriodicJobs() []*river.PeriodicJob` (package level); the integrator lists
  them in `internal/app/app.go` `NewWorker`.
